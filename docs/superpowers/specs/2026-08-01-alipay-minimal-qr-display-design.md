# 支付宝扫码支付极简展示设计

## 背景

当前支付中心在订单码支付二维码下方展示“立即查询”“刷新二维码”“切换官方收银台”等操作，
并在每次五秒轮询期间把“等待扫码支付”切换成“正在查询支付状态”。这些元素属于商户前端的
恢复与状态反馈设计，不是支付宝订单码支付要求展示的内容。

用户希望正常扫码支付界面与常见收银页一致：突出二维码，不暴露后台查单过程，同时保留订单号
方便支付问题核对。

## 已确认展示规则

扫码订单处于正常待支付状态时，只展示：

1. 商品名称与金额。
2. 支付宝二维码。
3. 二维码有效期。
4. 商户订单号。

隐藏以下内容：

- “立即查询”。
- 自动轮询期间的“正在查询支付状态”。
- “刷新二维码”。
- “重试二维码”。
- “打开付款链接”。
- “切换官方收银台”。

支付成功、订单过期或二维码异常时，仍显示必要的结果或错误信息，避免二维码消失后页面没有
反馈。错误恢复接口与后端能力继续保留，但不在正常二维码页面提供按钮入口。

## 方案比较

### 方案一：按支付状态控制极简界面

正常待支付与后台查询期间隐藏状态行和整个操作区；成功、过期或错误时再显示必要状态。
后台轮询和服务端查单保持不变。

优点：符合用户要求，同时保留关键异常与支付结果反馈。

缺点：二维码异常时不再向用户提供原有的页面内手动恢复按钮。

本次采用此方案。

### 方案二：始终隐藏状态与操作区

实现最简单，但支付成功或过期后只会看到二维码消失，用户无法判断发生了什么，不采用。

### 方案三：保留固定“等待扫码支付”提示

可以避免查询文案闪烁，但仍多展示一行状态，不符合“订单号保留，其他隐藏”的确认结果，
不采用。

## 前端行为

### 正常待支付与静默查单

- `QR_READY` 和自动轮询触发的 `QUERYING` 使用相同的可见布局。
- 二维码 Canvas 在查询期间保持可见，不闪烁、不重绘。
- 状态行隐藏，用户不会看到“正在查询支付状态”。
- 操作区整体隐藏，避免单个按钮的状态机重新将按钮显示出来。
- 每五秒轮询、页面重新可见后的立即同步、倒计时和 CSRF 保护全部保持现状。

### 支付结果与异常

- `PAID`：显示“支付成功，权益已到账”。
- `EXPIRED`：显示“订单已过期或关闭”。
- `QR_RENDER_ERROR`、`CREATE_ERROR`：显示现有安全错误说明，但不显示恢复按钮。
- 后台查单失败且订单仍可支付时，不把短暂网络错误暴露成正常页面的闪烁状态；自动轮询继续按
  既有逻辑重试。

## 数据与安全边界

- 不修改 `alipay.trade.precreate`、`alipay.trade.query`、异步通知验签或订单结算逻辑。
- 不根据前端倒计时或 Canvas 状态判定支付结果。
- 不删除刷新、切换收银台或主动查询的后端接口，避免扩大本次 UI 变更范围。
- 不记录或输出二维码原文、签名、密钥和支付宝完整响应。

## 测试范围

1. 模板仍包含订单号，正常支付操作区默认不展示。
2. `QR_READY` 和 `QUERYING` 时状态行隐藏，二维码保持可见。
3. 自动轮询仍以五秒间隔调用订单同步接口。
4. `PAID`、`EXPIRED` 和错误状态仍展示对应反馈。
5. 静态资源源目录与部署副本内容一致。

## 非目标

- 不修改会员价格、积分规则和权益发放。
- 不修改待支付订单页签及其恢复流程。
- 不改变支付宝订单二维码两小时有效期。
- 不调整官方收银台支付方式选择页。
