# 网站 Logo 全量替换与加载优化设计

## 背景

网站当前把同一张 1024×1024 PNG 用于导航栏、首页、登录注册页和图标场景。该文件约 1.4 MB，公网实测完整下载约 7.45 秒；`/favicon.ico` 当前还返回空响应。部分 Logo 由 `/site-logo.png` 或后端 Logo 接口提供，造成品牌图不一致，也引入不必要的远程依赖。

## 目标

- 所有网站品牌图形统一使用用户提供的新 Logo。
- 保留现有“海带 / AI 内容智能创作平台”文字标识。
- 页面展示 Logo 使用小尺寸本地静态资源，显著降低下载体积。
- favicon、Apple Touch Icon、SEO 分享图和旧 Logo 地址使用同一视觉来源。
- 保留 `/site-logo.png` 与 `/api/v1/common/site-logo/` 的兼容能力，不再请求后端或 OSS。

## 资源设计

以用户提供的 1254×1254 PNG 为唯一母版，生成下列本地资源：

- `site-logo-128.webp`：页面导航、登录、注册和绑定手机等常规展示位置。
- `site-logo-256.webp`：首页较大的 Hero Logo，并作为高密度屏幕候选资源。
- `logo.png`：512×512 优化 PNG，用于 SEO 分享图、旧 `/site-logo.png` 地址和不支持 WebP 的兼容场景。
- `favicon.png`：64×64 优化 PNG，用作现代浏览器 favicon。
- `apple-touch-icon.png`：180×180 优化 PNG，用于 iOS 主屏幕图标。

资源保持正方形、不裁切、不改变颜色和构图。HTML 为图片声明宽高，避免加载时布局抖动，并使用版本化本地静态 URL 便于长期缓存。

## 引用范围

统一更新以下位置：

- 全站基础模板的导航 Logo、favicon 和 Apple Touch Icon。
- 首页 Hero Logo。
- 登录、注册、绑定手机页面 Logo。
- SEO `og:image` 分享图。
- `/site-logo.png` 和 `/api/v1/common/site-logo/` 兼容端点。
- `/favicon.ico` 兼容入口。

文字品牌标识不修改。业务场景中“不要出现 LOGO”等提示词不属于站点品牌资源，不做替换。

## 请求与缓存流程

页面直接请求 `/static/images/` 下的本地资源，由 Nginx 静态文件服务返回，不再经过 Django 转发后端，也不再下载 OSS Logo。常规页面 Logo 优先使用 WebP；SEO 和旧地址兼容使用优化 PNG。旧端点返回本地文件或重定向到本地静态资源，并设置公共长期缓存。

若 WebP 不可用，`img` 的 PNG 回退仍能显示同一 Logo。图标端点不依赖后端，因此后端不可用时品牌资源仍可正常加载。

## 测试与验证

- 先添加失败测试，覆盖所有模板引用、favicon、SEO 图和旧端点不再访问后端/OSS。
- 验证生成资源的像素尺寸、格式和体积上限。
- 运行完整 Django 前端测试套件。
- 执行 `collectstatic`，确认生成目录包含所有新资源。
- 部署后通过公网检查 HTTP 200、内容类型、缓存头、文件体积和页面引用。
- 视觉抽查导航、首页、登录、注册和绑定手机页面，确认 Logo 正确且文字标识保留。
